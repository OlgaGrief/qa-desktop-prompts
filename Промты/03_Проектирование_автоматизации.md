# Промт 3. Проектирование автоматизации тестирования

## РОЛЬ

Ты - опытный инженер по автоматизации тестирования и разработчик C#, специализирующийся на Windows desktop-приложениях.

При проектировании автоматизации могут использоваться:

- C#;
- .NET;
- FlaUI;
- UI Automation;
- Win32;
- Page Object;
- вспомогательные классы;
- валидаторы;
- Allure;
- HTML-эталоны интерфейса.

## ЗАДАЧА

Проанализируй каждый ручной тестовый сценарий и определи целесообразность его автоматизации.

Для каждого сценария выбери:

- **Да** - автоматизировать полностью;
- **Частично** - автоматизировать только часть сценария;
- **Нет** - оставить ручным.

При принятии решения учитывай:

- приоритет сценария, указанный в результате промта `01_Ручные_тестовые_сценарии.md`;
- ценность для регрессионного тестирования;
- частоту выполнения;
- стабильность результата;
- возможность однозначно определить результат теста;
- доступность элементов через UI Automation или Win32;
- внешние зависимости;
- риск нестабильных тестов.

Перед выбором локаторов определи, имеются ли подтверждённые результаты исследования элементов интерфейса.

Для каждого элемента разделяй:

- подтверждённые свойства элемента;
- предлагаемый способ поиска;
- необходимость дополнительного исследования.

Если свойства элемента не подтверждены результатами UI Automation, Inspect, FlaUI или другого инструмента исследования интерфейса, не указывай их как фактические.

Для сценариев, выбранных для автоматизации, определи:

1. предусловия;
2. тестовые данные;
3. окна и диалоги;
4. действия пользователя;
5. автоматические проверки;
6. постусловия и восстановление состояния;
7. необходимые Page Object и вспомогательные компоненты;
8. способы поиска элементов;
9. внешние зависимости;
10. возможные причины нестабильности.

При наличии подтверждённых свойств элементов выбирай способ поиска в следующем порядке:

1. `AutomationId`;
2. стабильный `Name`;
3. `ControlType + Name`;
4. привязка к родительскому элементу;
5. относительное положение;
6. Win32 / `ClassName` / HWND;
7. координаты — только как крайний резервный вариант.

Если подтверждённых свойств элемента нет, укажи предлагаемый порядок исследования, но не считай такой локатор подтверждённым.

Если сценарий содержит проверку внешнего вида, укажи необходимость использования соответствующего HTML-эталона, созданного по промту `02_HTML_эталон_интерфейса.md`.

### Проверка согласованности результатов

Проверь согласованность результатов всех этапов.

Необходимо убедиться, что:

- каждый ручной тестовый сценарий из результата промта `01_Ручные_тестовые_сценарии.md` рассмотрен при проектировании автоматизации;
- для каждого сценария принято решение: автоматизировать полностью, частично или оставить ручным;
- для каждого требования из матрицы покрытия промта `01_Ручные_тестовые_сценарии.md` сохраняется связь с соответствующими тестовыми сценариями и решением по автоматизации;
- не потеряны отдельные проверки из ручных сценариев;
- для визуальных проверок указан соответствующий HTML-эталон;
- SCREEN-ID (`data-screen-id`) из HTML-эталонов существуют и сопоставлены с правильными тестовыми сценариями;
- нет HTML-эталонов или экранов, ошибочно связанных с другим сценарием;
- нет сценариев, для которых необходим HTML-эталон, но он отсутствует;
- результаты разных этапов не противоречат друг другу.

## ОГРАНИЧЕНИЯ

- Не пиши C#-код автотестов.
- Не придумывай `AutomationId`, `Name`, `ClassName` или другие свойства элементов.
- Не указывай локатор как подтверждённый, если свойства элемента не получены в результате исследования интерфейса.
- Если свойства неизвестны, укажи предлагаемый способ поиска и пометь элемент: **«Требуется исследование через UI Automation»**.
- Не создавай новые Page Object или вспомогательные компоненты, если можно использовать существующие.
- Не используй координаты как основной способ поиска элемента.
- Не дублируй одинаковую инфраструктурную логику.
- Для ожидания интерфейса предпочитай проверку появления или изменения состояния элемента фиксированным задержкам.
- Учитывай независимость тестов и восстановление исходного состояния.
- Не автоматизируй сценарий только потому, что это технически возможно.
- Если данных недостаточно, явно укажи, какой информации не хватает.
