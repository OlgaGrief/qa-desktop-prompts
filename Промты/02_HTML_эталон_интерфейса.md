# Промт 2. Создание HTML-эталона интерфейса

## РОЛЬ

Ты - опытный QA Automation Engineer с опытом тестирования Windows desktop-приложений, анализа UI и создания HTML/CSS-эталонов интерфейса для автоматизированных проверок.

## КОНТЕКСТ

Для приложения: **[НАЗВАНИЕ ПРИЛОЖЕНИЯ]** необходимо создать HTML-эталон интерфейса.

Я предоставляю изображения двух типов.

### Макеты

[ПРИЛОЖИТЕ ОДИН ИЛИ НЕСКОЛЬКО СКРИНШОТОВ ИЗ FIGMA]

### Эталонная реализация

[ПРИЛОЖИТЕ ОДИН ИЛИ НЕСКОЛЬКО СКРИНШОТОВ РЕАЛЬНОГО ПРИЛОЖЕНИЯ]

При необходимости изображения могут быть сгруппированы по экранам или состояниям:

- SCREEN-01 - [ОПИСАНИЕ];
- SCREEN-02 - [ОПИСАНИЕ];
- SCREEN-XX - [ДОБАВЬТЕ НУЖНОЕ КОЛИЧЕСТВО].

**Папка для хранения эталонов:** [УКАЖИТЕ ПУТЬ В ПРОЕКТЕ]

Макеты и скриншоты эталонной реализации используются совместно как источники для построения HTML-эталона или набора HTML-эталонов.

## ЗАДАЧА

На основании предоставленных изображений создай максимально точный и машиночитаемый HTML-эталон интерфейса.

Необходимо:

1. Восстановить структуру интерфейса:
   - окна;
   - панели;
   - секции;
   - подписи;
   - поля;
   - кнопки;
   - чекбоксы;
   - переключатели;
   - списки;
   - меню;
   - иконки;
   - другие видимые элементы.

2. Использовать:
   - макеты - как источник структуры, расположения, текстов, размеров и внешнего вида;
   - эталонную реализацию - как источник фактического отображения desktop-контролов, системных элементов и состояний.

3. Для значимых элементов добавить машиночитаемые атрибуты, пригодные для последующего использования из C#:

`data-screen-id`  
`data-name`  
`data-type`  
`data-text`  
`data-state`  
`data-x`  
`data-y`  
`data-width`  
`data-height`

Значение `data-screen-id` должно соответствовать идентификатору SCREEN-XX соответствующего экрана или состояния.

## ЦЕЛЬ

Получить стабильный HTML-эталон интерфейса, который можно хранить в проекте автоматизации и использовать для сравнения фактического интерфейса приложения с ожидаемым.

## ФОРМАТ

Подготовь:

1. `reference.html` либо отдельные `reference_*.html`, если разные состояния целесообразно хранить отдельно.
2. Рекомендуемую структуру папки.
3. Рекомендуемые имена исходных изображений.
4. Список элементов и состояний интерфейса, зафиксированных в HTML.
5. Список параметров, которые невозможно достоверно определить по предоставленным изображениям.

Если используется несколько SCREEN-XX, должна сохраняться однозначная связь между:

**SCREEN → исходные изображения → HTML-эталон.**

## ОГРАНИЧЕНИЯ

- Не сравнивай макеты и эталонную реализацию между собой.
- Не составляй отчёт об их различиях.
- Не придумывай отсутствующие элементы, тексты, состояния, размеры и координаты.
- Если параметр нельзя определить достоверно, используй `unknown` или явно укажи необходимость уточнения.
- Не смешивай разные SCREEN-XX и состояния.
- HTML должен быть автономным, читаемым и пригодным для последующего использования из C#.
- Решение должно быть универсальным для разных desktop-приложений.
