# Плейбук промтов для тестирования desktop-приложений

## Назначение

Плейбук предназначен для последовательного использования модели при подготовке ручного и автоматизированного тестирования Windows desktop-приложений.

Он охватывает три этапа:

1. Создание ручных тестовых сценариев по документации.
2. Создание HTML-эталона интерфейса по макетам и изображениям эталонной реализации;
3. Проектирование автоматизации на основании результатов первых двух этапов.

## Последовательность работы

### Этап 1. Ручные тестовые сценарии

**Входные данные:**
- Help;
- пользовательская документация;
- дополнительные требования;
- зарегистрированные ошибки;
- скриншоты при необходимости.

**Промт:**  
`01_Ручные_тестовые_сценарии.md`

**Результат:**  
набор ручных тестовых сценариев с предусловиями, шагами и ожидаемыми результатами.

---

### Этап 2. HTML-эталон интерфейса

**Входные данные:**
- макеты интерфейса из Figma;
- скриншоты эталонной реализации;
- описание экранов и состояний.

**Промт:**  
`02_HTML_эталон_интерфейса.md`

**Результат:**  
машиночитаемый HTML-эталон интерфейса, пригодный для последующего использования в автоматизированных UI-проверках.

Макеты и эталонная реализация на этом этапе не сравниваются между собой. Они используются совместно как источники для построения эталона.

---

### Этап 3. Проектирование автоматизации

**Входные данные:**
- ручные тестовые сценарии из этапа 1;
- HTML-эталоны из этапа 2, если требуются проверки интерфейса;
- существующая тестовая инфраструктура;
- сведения об элементах интерфейса и UI Automation.

**Промт:**  
`03_Проектирование_автоматизации.md`

**Результат:**  
технический план автоматизации с определением:
- какие сценарии автоматизировать полностью;
- какие автоматизировать частично;
- какие оставить ручными;
- какие элементы и локаторы использовать;
- какие Page Object и вспомогательные компоненты необходимы;
- какие HTML-эталоны использовать;
- какие существуют риски нестабильности.

## Используемый подход к построению промтов

Во всех трёх промтах используется единая структура:

**Роль + Контекст + Задача + Цель + Формат результата + Ограничения**

Это позволяет задавать модели роль, исходные данные, задачу, цель, формат результата и ограничения.

Дополнительно применяются:

- **Промт 1** — привязка к источнику требований;
- **Промт 2** — работа с несколькими источниками данных и запрет на неподтверждённые выводы;
- **Промт 3** — декомпозиция задачи, критерии принятия решения и фиксированный формат результата.

## Итог

Плейбук позволяет пройти путь от анализа требований и интерфейса до подготовки технического плана автоматизации без непосредственного написания программного кода.

Это делает промты переиспользуемыми для разных Windows desktop-приложений и позволяет применять их как единый последовательный процесс.
